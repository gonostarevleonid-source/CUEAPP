# CUEAPP — ТЗ и правила проекта

Кроссплатформенная (Windows + macOS) программа для **воспроизведения треков с таймкодом и прописи света под grandMA2/3**, для театра и концертов.
Основа интерфейса — вертикальный кью-лист и GO (как в QLab), но фокус другой:
**трек → таймлайн → маркеры → таймкод (LTC/MTC) → экспорт маркеров в grandMA**. Плюс точечные MIDI/OSC-триггеры на маркерах.

Визуальный макет (Edit mode, Show mode, Экспорт в grandMA, Настройки проекта) сделан в Claude Design:
https://claude.ai/artifact/N6EMjnN7FAkVMfZDoMnk1u — при вопросах по интерфейсу
ориентироваться на него и на раздел «Дизайн» ниже.

> **Изменение концепции (8 ноября 2026).** Убраны: петли и бесконечное/многократное воспроизведение трека или его части, auto-continue и auto-follow, отдельные типы Audio/Fade/Wait (вместо них один тип «Трек» с таймлайном). Добавлен экспорт маркеров в grandMA2/3. Если в коде уже есть реализация убранного — удалить её аккуратно (с тестами), не ломая остальное. Сначала покажи мне план изменений.

## 1. Технологии

- **Язык:** C# / .NET (последняя LTS-версия).
- **Интерфейс:** Avalonia UI (одинаково на Windows и macOS). Паттерн MVVM (CommunityToolkit.Mvvm).
- **Аудио:** ManagedBass (BASS) — ASIO/WASAPI на Windows, CoreAudio на Mac. Аудио спрятано за собственным интерфейсом `IAudioEngine`, чтобы можно было сменить библиотеку.
- **MIDI:** DryWetMidi (вывод сообщений, вход для управления, MTC).
- **OSC:** легкая библиотека (например, Rug.Osc / CoreOSC) или своя реализация поверх UDP.
- **DMX:** Art-Net и sACN по UDP (своя небольшая реализация или библиотека).
- **LTC:** генерация аудиосигнала LTC самостоятельно (кодирование кадров в аудио) на выбранный аудиовыход.
- **Формат шоу:** JSON-файл `.cue` (System.Text.Json), человекочитаемый.
- **Git + GitHub** — код синхронизируется между Windows и Mac.
- Позже: видео (LibVLC или mpv) и NDI.

Разработка в основном на Windows, регулярная проверка на Mac.

## 2. Архитектура (слои)

```
CueApp.Core      — модель шоу, кью, плейхед, GO, тайминг, петли, отсчеты. Без зависимостей от UI и ОС.
CueApp.Audio     — IAudioEngine + реализация на BASS (воспроизведение, фейды, выходы, LTC).
CueApp.Control   — MIDI, MTC, OSC, Art-Net/sACN (IOutputDevice-подобные сервисы).
CueApp.App       — Avalonia UI (окна, ViewModels).
CueApp.Tests     — тесты ядра (тайминг, петли, отсчет, логика GO).
```

Ключевые принципы:
- **Ядро не знает про UI и про конкретные библиотеки.** Всё общение — через интерфейсы.
- **Одни часы на всё:** таймлайн, маркеры, таймкод и отсчеты считаются от позиции воспроизведения аудио (а не от системного таймера UI), чтобы ничего не расходилось.
- Отправка событий (MIDI/OSC/DMX) — из отдельного потока планировщика с высокой точностью, не из UI-потока.
- Маркер на таймлайне может запускать «что угодно» (действие) — это задел под видео/NDI.

## 3. Кью-лист и логика GO

- Вертикальный список кью сверху вниз. **Только GO / Stop** — никаких auto-continue / auto-follow (пока).
- Нумерация: 1, 2, 3… Подкью в группе: 1.1, 1.2… **Подкью визуально смещены вправо** относительно родителя (вся строка), тонкая вертикальная линия слева; номер подкью — обычный шрифт, основной кью — жирный.
- Колонки: №, Тип, Название, Старт TC, Длительность (у играющей — обратный отсчет), Маркеры (сводка: «MA 9 · MIDI 2 · OSC 3»).
- Добавление трека: кнопка «Трек» или **перетаскивание аудиофайлов** в список (каждый файл → новая кью «Трек»).
- **Выбранная кью** (уйдет по GO): белая обводка + зеленая полоска слева. Выделенная ≠ играющая.
- **После GO выделение перескакивает на следующую кью** (с группы — на первую подкью).
- Клик по кью делает ее выбранной.
- **Играющая кью** — синий фон + синяя полоска.
- **Цвет кью:** 8 приглушенных заливок строки (нет, красный, оранжевый, желтый, зеленый, синий, фиолетовый, розовый).
- GO во время играющего трека разрешен; в настройках — галочка «Блокировать запуск кью, пока играет трек». **Stop и Panic работают всегда.**
- Защита от двойного GO (300 мс по умолчанию). Кнопки: GO, STOP, PANIC (фейд всего 0.5 с).

### Типы кью
| Тип | Этап | Суть |
|---|---|---|
| **Трек** | v1 | Аудиофайл + свой таймлайн с маркерами + таймкод. Trim in/out, fade in/out, громкость, выход. Играет один раз: GO → до конца или до Stop |
| Stop | v1 | Останавливает одну кью или все, с фейдом |
| Group | v1 | Группа (1 → 1.1, 1.2…) для структуры шоу (блоки, акты) |
| MIDI | v2 | Отдельная MIDI-кью по GO (Note / CC / PC / MSC) |
| OSC | v2 | Отдельная OSC-кью по GO |
| DMX, видео, NDI | позже | — |

## 4. Трек и таймлайн (главная фича)

- В кью-листе трек — одна строка; в нижней панели — его таймлайн.
- Волновая форма, линейка времени, зум, прокрутка, именованные метки секций («Припев», «Бридж»).
- **Дорожки:**
  1. **Таймкод** — диапазон TC трека.
  2. **Свет · grandMA** — маркеры, которые экспортируются в консоль (каждый маркер = будущая кью в секвенции MA). У маркера: номер кью MA, имя, (опц.) цвет.
  3. **MIDI** — маркеры-триггеры (Note/CC/PC/MSC), отправляются программой во время воспроизведения.
  4. **OSC** — маркеры-триггеры (адрес + аргументы, получатель).
- Маркеры ставятся: мышкой, вводом точного времени, **Tap-маркер (клавиша M)** вживую во время воспроизведения (на выбранную дорожку). Потом двигаются, удаляются, копируются группами. Snap к сетке BPM и к другим маркерам.
- Номера кью MA на дорожке «Свет» нумеруются автоматически по порядку (1, 2, 3…), с возможностью задать вручную (в т.ч. дробные — 2.5).
- **Маркеры хранятся во времени аудиофайла.** Меняешь trim in, фейд, точку старта — маркеры НЕ съезжают относительно ударов. Маркер в обрезанной части не удаляется, а становится серым/неактивным (и не экспортируется).
- Нижняя панель **всегда показывает играющий трек**; инспектор и заметки — выбранную кью. Если ничего не играет — показывается выбранный трек (для расстановки маркеров).
- Если играют два трека одновременно — вкладки над таймлайном, последний запущенный открыт.

## 5. Таймкод (как было)

- **LTC** (аудио на выбранный выход, уровень настраивается) и **MTC** (на MIDI-порт). Можно оба одновременно.
- Частоты: 24, 25, 29.97 DF, 29.97 NDF, 30.
- Значения по умолчанию — в настройках проекта; у каждого трека: свой старт TC (например 01:12:00:00), частота, выходы.
- **Таймкод привязан ко времени файла**: TC = старт TC трека + позиция в файле. Подрезал начало — свет в MA не съезжает.
- Запуск трека с середины → таймкод идет с соответствующего места. Pre-roll опционально.
- По умолчанию треки получают непересекающиеся стартовые TC (например, каждый следующий — +00:05:00:00 после конца предыдущего, округлено), можно изменить.

## 6. Экспорт маркеров в grandMA2 / grandMA3

Цель: расставил маркеры на дорожке «Свет» → одной кнопкой получил в консоли готовый таймкод-шоу, где на каждом маркере стоит Go нужной кью; дальше художник по свету только прописывает свет в кью.

- Окно «Экспорт в grandMA» (см. макет): консоль (MA3 / MA2) и версия софта; номер Timecode-объекта, номер Sequence, Executor/Page; fps и старт TC (из трека); галочки «имя маркера → имя кью», «цвет маркера → цвет кью»; fade кью по умолчанию (0).
- **Маркер = кью в секвенции + событие Go этой кью в таймкод-объекте** на времени TC маркера.
- Предпросмотр: таблица «Кью · Имя · Таймкод · Событие», с галочками, какие маркеры экспортировать. Неактивные (вне trim) не экспортируются.
- Экспорт одного трека или всех треков шоу (каждому треку — свой Timecode и Sequence, нумерация по правилам из настроек).
- **Повторный экспорт:** по умолчанию «обновить время событий, свет в кью не трогать»; варианты: перезаписать полностью / создать с новым номером.
- **Способ v1 — XML-файлы** для импорта на консоли:
  - grandMA3: XML timecode-объекта и секвенции для `Import Timecode` / `Import Sequence` (папки `gma3_library/datapools/timecodes`, `.../sequences`); можно сохранять сразу на USB.
  - grandMA2: XML для импорта через Import (папка `importexport`), либо макрос, создающий секвенцию и таймкод.
- **Способ позже — напрямую по сети:** MA3 по OSC (команды командной строки), MA2 по Telnet.
- ⚠️ Точную структуру XML не выдумывать. Порядок: я экспортирую с консоли / onPC эталонные файлы (`Export Timecode 1`, `Export Sequence 1` на MA3, аналог на MA2) и кладу в `samples/grandma/`; ты разбираешь их и пишешь генератор по образцу. Проверка — импорт в grandMA3 onPC / grandMA2 onPC. Генератор покрыть тестами (сравнение с эталоном).
- Экспорт маркеров также в CSV (время, TC, имя) — для других консолей и для проверки.

## 7. Отсчеты и предупреждения

- Обратный отсчет «осталось» — с учетом trim и фейдов.
- Цвета: > 30 с — синий; ≤ 30 с — желтый; ≤ 10 с — красный и мигает. Пороги — в настройках.
- Отсчет до следующего маркера (особенно MA-кью: «до MA Cue 6 −0:09.1») и до следующей метки.
- Активные кью: у каждой играющей кью свой отсчет; в Show mode — блок активных кью с кнопкой стоп у каждой.
- Формат времени: м:сс.д (по умолчанию), м:сс, кадры таймкода.

## 8. Заметки и режимы Edit / Show

- У каждой кью — заметки (многострочный текст). Edit: блок справа над инспектором (вкладки инспектора: Трек, Таймкод, grandMA, Выходы). Show: крупно заметки следующей и играющей кью.
- **Edit:** шапка (Edit/Show, Настройки, Экспорт в grandMA, Играет/Следующая, окно таймкода, Panic/Stop/GO), кью-лист, справа заметки + инспектор, снизу таймлайн.
- **Show:** огромная GO с названием следующей кью; текущая кью (таймкод, прошло/осталось, ближайшие MA/MIDI/OSC-события); упрощенный список; активные кью; заметки; индикаторы выходов и связи. Редактирование заблокировано; выход в Edit с защитой.

## 9. Настройки проекта (сохраняются в шоу-файле)

- **Воспроизведение:** блокировка GO во время трека; переход выделения после GO; фейды Stop/Panic.
- **Отсчет:** пороги, мигание, отсчет до маркера, формат времени.
- **Аудио:** драйвер (ASIO/WASAPI на Win, CoreAudio на Mac), устройство, частота, буфер; именованные выходы.
- **Таймкод:** LTC/MTC, fps по умолчанию, выход LTC и уровень, порт MTC, pre-roll, правило стартовых TC новых треков.
- **grandMA:** консоль по умолчанию (MA3 2.x / MA2), нумерация Timecode и Sequence (например «100 + номер трека»), executor/page, папка экспорта, поведение повторного экспорта; прямая отправка по сети — позже.
- **MIDI:** выход по умолчанию; вход для управления (GO/Stop/Panic с контроллера).
- **OSC:** входящий порт; список получателей (имя, IP, порт).
- **Show mode:** блокировка редактирования, защита выхода, защита от двойного GO, клавиша GO (Пробел).
- DMX, видео, NDI — зарезервировано.

## 11. Этапы разработки

**Этап 0 — подготовка** (сделан)
- Solution, проекты, Git, BASS, окно Avalonia.

**Этап 1 — плеер треков с таймкодом (MVP)**
- Привести код к новой концепции (убрать петли/повторы, auto-continue/follow, лишние типы кью).

- MIDI/OSC-маркеры на таймлайне и отдельные MIDI/OSC-кью; вход управления (GO/Stop/Panic по MIDI и OSC).

**Сборка релиза:** `dotnet publish` — самостоятельный exe для Windows и `.app` для macOS, скрипты сборки.

## 12. Требования к надежности (это софт для живых шоу)

- Ничто в UI не должно тормозить звук и отправку событий.
- Ошибка одного устройства (отвалился MIDI-интерфейс, нет сети) не роняет программу — показываем предупреждение, остальное продолжает работать.
- Автосохранение и резервная копия шоу-файла.
- Ядро (тайминг, таймкод, отсчеты, маркеры при изменении trim, генератор экспорта grandMA) покрыто тестами.
