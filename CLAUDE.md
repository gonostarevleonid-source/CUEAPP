# CUEAPP — ТЗ и правила проекта

Кроссплатформенная (Windows + macOS) программа show control для театра и концертов.
Идея: взять лучшее от QLab (вертикальный кью-лист, GO, плейхед) и улучшить —
главное отличие: **Timeline cue** с маркерами MIDI/OSC/DMX прямо на волновой форме трека
и генерация таймкода (LTC/MTC) для grandMA3.

Визуальный макет (Edit mode, Show mode, Настройки проекта) сделан в Claude Design:
https://claude.ai/artifact/N6EMjnN7FAkVMfZDoMnk1u — при вопросах по интерфейсу
ориентироваться на него и на раздел «Дизайн» ниже.

## 1. Технологии

- **Язык:** C# / .NET (последняя LTS-версия).
- **Интерфейс:** Avalonia UI (одинаково на Windows и macOS). Паттерн MVVM (CommunityToolkit.Mvvm).
- **Аудио:** ManagedBass (BASS) — ASIO/WASAPI на Windows, CoreAudio на Mac. Аудио спрятано за собственным интерфейсом `IAudioEngine`, чтобы можно было сменить библиотеку.
- **MIDI:** DryWetMidi (вывод сообщений, вход для управления, MTC).
- **OSC:** легкая библиотека (например, Rug.Osc / CoreOSC) или своя реализация поверх UDP.
- **DMX:** Art-Net и sACN по UDP (своя небольшая реализация или библиотека).
- **LTC:** генерация аудиосигнала LTC самостоятельно (кодирование кадров в аудио) на выбранный аудиовыход.
- **Формат шоу:** JSON-файл `.cue` (System.Text.Json), человекочитаемый.
- **Git + GitHub** — код синхронизируется между Windows и Mac.
- Позже: видео (LibVLC или mpv) и NDI.

Разработка в основном на Windows, регулярная проверка на Mac.

## 2. Архитектура (слои)

```
CueApp.Core      — модель шоу, кью, плейхед, GO, тайминг, петли, отсчеты. Без зависимостей от UI и ОС.
CueApp.Audio     — IAudioEngine + реализация на BASS (воспроизведение, фейды, выходы, LTC).
CueApp.Control   — MIDI, MTC, OSC, Art-Net/sACN (IOutputDevice-подобные сервисы).
CueApp.App       — Avalonia UI (окна, ViewModels).
CueApp.Tests     — тесты ядра (тайминг, петли, отсчет, логика GO).
```

Ключевые принципы:
- **Ядро не знает про UI и про конкретные библиотеки.** Всё общение — через интерфейсы.
- **Одни часы на всё:** таймлайн, маркеры, таймкод и отсчеты считаются от позиции воспроизведения аудио (а не от системного таймера UI), чтобы ничего не расходилось.
- Отправка событий (MIDI/OSC/DMX) — из отдельного потока планировщика с высокой точностью, не из UI-потока.
- Маркер на таймлайне может запускать «что угодно» (действие) — это задел под видео/NDI.

## 3. Кью-лист и логика GO

- Вертикальный список кью сверху вниз, как в QLab.
- Нумерация: 1, 2, 3… Подкью: 4.1, 4.2, 4.3 (в будущем допустим второй уровень 4.2.1).
- **Подкью визуально смещены вправо** относительно родителя (вся строка), с тонкой вертикальной линией слева и чуть более светлым фоном; номер подкью — обычный шрифт, номер основной кью — жирный. Колонки времени остаются выровнены.
- Колонки: №, Тип, Название, Pre-wait, Длительность, Post-wait, Continue (auto-continue / auto-follow).
- **Выбранная кью** (плейхед, «уйдет по GO»): белая обводка строки + зеленая полоска слева. Выделенная ≠ играющая.
- **После GO выделение перескакивает на следующую кью** (с группы — по настройке: на первую подкью или на следующую основную).
- Клик по любой кью делает ее выбранной — следующий GO запустит её.
- **Играющая кью** подсвечивается синим фоном + синей полоской.
- **Цвет кью:** в инспекторе можно выбрать заливку строки из 8 приглушенных цветов: нет, красный, оранжевый, желтый, зеленый, синий, фиолетовый, розовый (темные, чтобы текст читался и подсветки состояния были видны поверх).
- **GO во время таймлайна:** по умолчанию разрешен (можно запускать другие кью параллельно). В настройках проекта галочка «Блокировать запуск кью, пока играет таймлайн»: блокирует GO, клик-запуск и внешние триггеры (MIDI/OSC). **Stop и Panic работают всегда.** При блокировке кнопка GO серая с замком.
- Защита от двойного GO (по умолчанию 300 мс).
- Кнопки: GO (большая, зеленая), STOP, PANIC (фейд всего, по умолчанию 0.5 с).

### Типы кью
| Тип | Этап | Суть |
|---|---|---|
| Audio | v1 | Файл, trim in/out, fade in/out, громкость, выход(ы), повтор (1 / N / ∞), петля на фрагменте |
| Fade | v1 | Плавно меняет громкость целевой кью за N с (кривые: линейная, S) |
| Stop | v1 | Останавливает одну кью или все, с фейдом |
| Wait | v1 | Пауза |
| Group | v1 | Группа подкью (4 → 4.1, 4.2…) |
| Timeline | v2 | Трек + маркеры событий + таймкод (см. ниже) |
| MIDI | v2 | Note / CC / Program Change / MSC |
| OSC | v2 | Адрес + аргументы на выбранного получателя |
| DMX | v3 | Сцена: значения каналов во вселенной, с фейдом |
| Video / NDI | позже | — |

## 4. Timeline cue (главная фича)

- В кью-листе — одна строка; внутри — свой редактор в нижней панели.
- Волновая форма трека, линейка времени, зум, прокрутка.
- **Дорожки:** Таймкод, MIDI, OSC, DMX (отдельные, чтобы не было каши).
- **Маркеры** ставятся прямо на шкалу: мышкой, вводом точного времени или **Tap-маркер (клавиша M)** — нажимаешь вживую во время воспроизведения. Потом можно двигать.
- **Именованные метки** секций («Припев 1», «Бридж», «Финал»).
- Привязка (snap) к сетке BPM и к другим маркерам; копирование групп маркеров.
- **Маркеры хранятся во времени аудиофайла.** Если поменяли trim in, фейд, точку старта — маркеры НЕ съезжают относительно ударов. Маркер, попавший в обрезанную часть, не удаляется, а становится серым/неактивным; вернули кусок — снова активен.
- **Таймкод тоже привязан ко времени файла** (подрезали начало — свет в grandMA3 не съезжает).
- Нижняя панель таймлайна **всегда показывает играющую Timeline cue**, а не выбранную. (Инспектор и заметки показывают выбранную.)
- Если играет несколько Timeline cue одновременно: показывается последняя запущенная, над панелью вкладки активных таймлайнов («● 12 · Финальная песня», «● 17 · Танго (−0:48.2)»), переключение одним кликом; когда одна заканчивается — панель переходит на оставшуюся.
- Если ничего не играет — панель показывает последний сыгранный таймлайн (серым). Двойной клик по Timeline cue открывает её для редактирования.

### Петли и повторы
- Повтор всего трека: 1 раз / N раз / ∞.
- **Петля на фрагменте:** выделить участок на таймлайне → «Петля из выделения» (L). Число проходов N или ∞. На волновой форме — синяя зона со счетчиком «↻ × 4 · проход 2/4».
- Выход из петли: кнопка «Выйти из петли» (в Show mode тоже). Режим (в настройках кью / проекта): «доиграть текущий проход → дальше» (по умолчанию) или «сразу».
- **Маркеры внутри петли срабатывают на каждом проходе** (по умолчанию); у каждого маркера есть галочка «только на первом проходе».
- **Таймкод в петле прыгает назад вместе с музыкой** (grandMA3 повторяет тот же свет на каждом проходе).

## 5. Таймкод

- **LTC** (аудио на выбранный выход звуковой карты, уровень настраивается) и **MTC** (на выбранный MIDI-порт). Можно оба одновременно.
- Частоты: 24, 25, 29.97 DF, 29.97 NDF, 30.
- Значения по умолчанию — в настройках проекта; у каждой Timeline cue можно переопределить частоту, стартовое время (например 01:12:00:00) и выходы.
- Запуск трека с середины → таймкод идет с соответствующего места.
- Pre-roll (например, 2 с) перед стартом трека — опционально.

---

## 6. Отсчеты и предупреждения

- Обратный отсчет «осталось» — с учетом trim, фейдов и **оставшихся проходов петли**. Бесконечная петля → «∞».
- Цвета: > 30 с — синий; ≤ 30 с — желтый; ≤ 10 с — красный и мигает. Пороги — в настройках проекта.
- Отсчет до следующего маркера и до следующей метки («до «Бридж» −0:32.3»).
- **Активные кью:** у каждой играющей кью свой отсчет; в Show mode — отдельный блок со списком активных кью и кнопкой стоп у каждой.
- Loop-кью (∞) показывают прошедшее время («∞ 12:41»).
- Формат времени: м:сс.д (по умолчанию), м:сс, кадры таймкода.

---

## 7. Заметки

- У каждой кью — поле заметок (многострочный текст) + метки-теги.
- Edit mode: блок заметок выбранной кью справа над инспектором.
- Show mode: крупные заметки следующей кью + заметки играющей.

---

## 8. Режимы Edit / Show

- **Edit:** полный интерфейс — шапка, кью-лист, справа заметки + инспектор (вкладки: Основное, Таймкод, Выходы, Триггеры), снизу таймлайн.
- **Show:** всё крупно; огромная GO с названием следующей кью; карточка текущей кью (таймкод, прошло/осталось, прогресс с метками секций, ближайшие MIDI/OSC); упрощенный список; активные кью; заметки; индикаторы выходов и связи (MIDI · OSC · Art-Net). Редактирование заблокировано; выход в Edit — с защитой (удержание или пароль).

## 9. Настройки проекта (сохраняются в шоу-файле)

- **Воспроизведение:** блокировка GO во время таймлайна; переход выделения после GO; поведение с подкью; фейды Stop/Panic; выход из петли; маркеры в петле.
- **Отсчет:** пороги, мигание, учет петель, отсчет до маркера, формат времени.
- **Аудио:** драйвер (ASIO/WASAPI на Win, CoreAudio на Mac), устройство, частота, буфер; таблица именованных выходов (Main L/R, Sub, Monitors, LTC…).
- **Таймкод:** LTC/MTC вкл/выкл, fps по умолчанию, выход LTC и уровень, порт MTC, pre-roll.
- **MIDI:** выход по умолчанию; вход для управления (GO/Stop/Panic с контроллера, назначаемые ноты).
- **OSC:** входящий порт (управление программой); список получателей (имя, IP, порт).
- **DMX:** сетевой интерфейс; вселенные (номер, Art-Net/sACN, адрес/broadcast/multicast, приоритет sACN); галочка «не слать DMX, пока нет активных DMX-кью» (не мешать grandMA3).
- **Show mode:** блокировка редактирования, защита выхода, крупные заметки, защита от двойного GO, клавиша GO (по умолчанию Пробел).
- **Видео и NDI:** зарезервировано.

## 11. Этапы разработки

**Этап 0 — подготовка**
- Создать solution и проекты по разделу 2, Git, .gitignore, README.
- Окно Avalonia с темной темой и кнопкой GO, которая проигрывает тестовый звук через BASS. Проверить на Windows и Mac.

**Этап 1 — MVP (можно использовать на репетиции)**
- Модель шоу, сохранение/загрузка `.cue`.
- Кью-лист: добавление, удаление, перетаскивание, нумерация, подкью со смещением, цвета, выделение.
- GO / Stop / Panic, плейхед и переход выделения.
- Audio (trim, fade, громкость, выход, повтор 1/N/∞), Fade, Stop, Wait, Group; pre/post-wait, auto-continue/follow.
- Отсчеты и цветовые предупреждения, блок активных кью.
- Заметки, инспектор.
- Edit / Show mode.
- Настройки: аудио, воспроизведение, отсчет, Show mode.

**Этап 2 — Timeline + управление**
- Timeline cue: волновая форма, зум, маркеры, tap-маркеры, метки, snap, петли на фрагменте.
- MIDI (выход + вход управления), OSC (выход + вход управления).
- Таймкод LTC и MTC, все fps, привязка ко времени файла, поведение в петле.
- Вкладки активных таймлайнов.

**Этап 3 — DMX**
- Art-Net / sACN, DMX-кью и DMX-маркеры.

**Этап 4 — Видео и NDI.**

**Сборка релиза:** `dotnet publish` — один самостоятельный exe для Windows (self-contained, single file) и `.app` для macOS. Подготовить скрипты сборки.

## 12. Требования к надежности (это софт для живых шоу)

- Ничто в UI не должно тормозить звук и отправку событий.
- Ошибка одного устройства (отвалился MIDI-интерфейс, нет сети) не роняет программу — показываем предупреждение, остальное продолжает работать.
- Автосохранение и резервная копия шоу-файла.
- Ядро (тайминг, петли, отсчеты, маркеры при изменении trim) покрыто тестами.
